# Bigdata Platform 平台总览

## 1. 平台定位

Bigdata Platform 是一套面向企业级数据处理场景的大数据平台方案，目标是同时支持传统数仓和实时数据湖两类核心场景，并能够在不同基础设施环境中灵活部署与交付。

平台第一阶段以物理机和传统 Hadoop 生态为主要落地方向，使用 Apache Ambari 作为集群管理面，使用 Apache Bigtop 作为组件构建、版本管理和包发行的参考体系。后续阶段逐步扩展到虚拟机、容器平台和云原生运行环境。

平台最终目标是形成一套可扩展、可组合、可交付的大数据平台体系：

- 支持传统离线数仓
- 支持实时数据湖
- 支持物理机部署
- 支持虚拟机部署
- 远期支持容器平台部署
- 支持大数据组件按需组合
- 支持组件自定义扩展
- 支持标准化安装、配置、监控、运维和验证

## 2. 核心目标

### 2.1 同时支持传统数仓与实时数据湖

平台不是单一 Hadoop 集群，也不是单一实时计算平台，而是同时面向两类数据架构：

| 架构类型 | 核心能力 | 典型组件 |
|---|---|---|
| 传统数仓 | 批量接入、离线计算、分层建模、SQL 分析 | HDFS、YARN、Hive、Spark、MapReduce |
| 实时数据湖 | CDC 接入、流式处理、湖仓表格式、近实时查询 | Kafka、Flink、Spark、Iceberg/Hudi、Trino |

第一阶段优先完成传统数仓底座，后续逐步扩展实时数据湖能力。

### 2.2 支持多种部署形态

平台需要具备从传统部署到云原生部署的演进能力：

| 阶段 | 部署形态 | 说明 |
|---|---|---|
| 第一阶段 | 物理机 | 适合传统 Hadoop 集群、稳定资源池、私有化交付 |
| 第二阶段 | 虚拟机 | 适合资源隔离、弹性扩展、测试/生产多环境部署 |
| 第三阶段 | 容器平台 | 适合云原生组件、Operator、弹性计算和平台化交付 |

### 2.3 支持组件自定义扩展与灵活组合

平台需要支持不同客户、不同场景、不同规模下的组件组合。例如：

```text
最小离线数仓组合：
HDFS + YARN + Hive + Spark + ZooKeeper

实时接入组合：
Kafka + Flink + CDC Connector + HDFS/Object Storage

实时数据湖组合：
Kafka + Flink + Iceberg/Hudi + Trino + Hive Metastore

安全治理组合：
Kerberos + Ranger + Knox + Atlas
```

组件不应硬编码为单一发行版，而应通过版本矩阵、组件包、配置模板、部署拓扑和运维手册进行组合式交付。

## 4. 关键设计原则

### 4.1 先稳定，后扩展

第一阶段优先确保传统 Hadoop 数仓底座可靠可交付，再扩展实时数据湖和云原生能力。

### 4.2 先文档，后工程

设计规划阶段先明确平台定位、组件边界、部署模型、阶段计划、验证标准和运维流程，再进入脚本、Stack、Operator 等工程实现。

### 4.3 组件可插拔

大数据组件应以模块方式被定义和交付，避免平台绑定单一组件组合。

### 4.4 部署形态可演进

平台第一阶段基于物理机和 Ambari 管理传统 Hadoop 集群；后续支持虚拟机部署；远期通过 Kubernetes / Operator 管理云原生数据组件。

### 4.5 交付闭环

每个阶段都必须形成完整闭环：

```text
设计文档 -> 版本矩阵 -> 部署方案 -> 配置模板 -> 验证方案 -> 运维手册
```

## 5. 第一阶段范围

第一阶段聚焦传统数仓底座，目标是在物理机环境中形成可安装、可管理、可验证的大数据平台基础版本。

### 5.1 第一阶段核心组件

- HDFS
- YARN
- Hive
- Spark
- ZooKeeper
- Ambari
- Bigtop 参考构建体系

### 5.2 第一阶段暂缓组件

以下能力进入后续阶段，不作为第一阶段主线目标：

- Kafka
- Flink
- Iceberg / Hudi / Delta Lake
- Trino
- Ranger
- Atlas
- Knox
- Kubernetes / Operator
- 自定义 Ambari Stack 的完整生产实现

## 6. 目标用户与使用场景

### 6.1 目标用户

- 大数据平台研发团队
- 数据平台运维团队
- 私有化交付团队
- 企业数据中台建设团队
- 需要离线数仓与实时数据湖统一规划的团队

### 6.2 使用场景

- 企业内部 Hadoop 集群建设
- 离线数仓底座交付
- 实时数据湖平台规划
- 私有化大数据平台交付
- 多组件大数据平台方案沉淀
- 从传统大数据向云原生数据平台演进

## 7. 非目标

当前阶段不追求：

- 立即实现完整商业化管理控制台
- 立即实现所有大数据组件的一键安装
- 立即实现全量 Kubernetes 云原生架构
- 立即维护完整自定义大数据发行版
- 立即覆盖所有安全治理和元数据治理能力

这些能力应进入后续路线图，避免第一阶段过重。

## 8. 平台最终形态

平台最终应形成如下能力：

```text
可构建：通过 Bigtop 或等价体系构建组件包
可安装：通过 Ambari / Blueprint / 自动化流程安装集群
可组合：按场景选择数仓、数据湖、实时、治理组件
可管理：统一管理服务、配置、状态、告警和生命周期
可验证：通过 Service Check、Smoke Test、集成测试验证交付结果
可运维：通过 Runbook、巡检脚本、恢复流程支撑生产运维
可演进：从物理机到虚拟机，再到容器平台和云原生架构
```
